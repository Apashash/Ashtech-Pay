💳 INTÉGRATIONS API — Problèmes détectés
❌ Sécurité Webhooks — Optionnelle si WEBHOOK_SECRET absent
Dans routes.ts lignes ~11158, ~11284, ~11492 : la vérification du token webhook Swychr, AfribaPay et PixPay est entièrement bypassée si WEBHOOK_SECRET n'est pas défini en variable d'environnement. N'importe qui peut envoyer un faux webhook et créditer un wallet.

❌ PixPay — Terminologie inversée
PixPay nomme cash_out les collectes (dépôts) et cash_in les retraits — c'est l'inverse de la logique standard. Le code gère ça via getPixPayServiceId() mais c'est une source de confusion en cas de débogage.

⚠️ Swychr Payout — Pas de retry sur 401
Le code Payin (server/swychr.ts) a un mécanisme auto-retry si le token expire (erreur 401). Le code Payout (server/swychrPayout.ts) n'a pas ce mécanisme — un token expiré en cours de nuit peut bloquer tous les retraits sans relance automatique.

⚠️ PixPay — Retourne HTTP 200 même en cas d'erreur
PixPay répond toujours 200 OK même si la transaction échoue. Le code vérifie data.statut_code !== 200 mais si le format de réponse change légèrement côté PixPay, les erreurs passeront silencieusement comme des succès.

⚠️ AfribaPay — Token caché dans un fichier local
Le token AfribaPay est mis en cache dans .local/afribapay_token.json. En cas de redémarrage ou déploiement, ce fichier peut être absent, forçant une ré-authentification. Ce n'est pas un bug mais une fragilité en multi-instance.

3. 📚 DOCUMENTATION — Écarts détectés
❌ Nombre de pays incohérent
Page	Valeur affichée
hosted-page-docs.tsx	"16+ pays"
pdf-docs.ts	"22+ pays"
Deux chiffres différents dans deux docs officielles.

❌ Paramètre :id vs :payment_id
L'endpoint GET /api/v1/hosted-payment/:payment_id est documenté avec :payment_id mais implémenté avec :id dans routes.ts. Un développeur qui copie l'URL de la doc et tente de parser le paramètre req.params.payment_id obtiendra undefined.

⚠️ Endpoints publics non documentés
Ces routes existent en production mais ne sont nulle part dans la doc :

GET /api/public/countries
GET /api/public/hosted-session/:id
POST /api/public/hosted-session/:id/pay
GET /api/public/hosted-session/:id/status
