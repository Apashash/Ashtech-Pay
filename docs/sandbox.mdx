## Stratégie de test

Testez au minimum :

- une réponse `200` sur `/v1/countries` et `/v1/fees` ;
- un paiement Mobile Money `pending`, `completed` et `failed` ;
- la réception d'un webhook ;
- la déduplication d'un même webhook ;
- un timeout après lequel vous vérifiez le statut au lieu de créer un second paiement ;
- les erreurs `400`, `401`, `403` et `429`.

## Environnement de démonstration

Le dashboard AshTech Pay contient des outils de test pour les parcours de paiement. N'utilisez jamais de vraies clés dans des captures d'écran, des logs ou un dépôt Git.

<Note>
  Les numéros ci-dessous sont fictifs. Ils ne correspondent à aucun abonné et ne doivent jamais être utilisés avec un autre service de paiement.
</Note>

### Réponses simulées

| Numéro utilisé | Réponse |
| --- | --- |
| `...000000001` | HTTP `200`, `status: "success"` |
| `...000000002` | HTTP `202`, `status: "pending"` |
| `...000000003` | HTTP `200`, `status: "failed"` |
| `...000000004` | HTTP `400`, `error: "otp_required"` ; relancez avec `otp: "000000"` pour obtenir `status: "pending"` |
| `...000000005` | HTTP `200`, `status: "cancelled"` |

Toutes ces réponses contiennent `sandbox: true` et `simulation: true`. Elles ne créent pas de transaction, n'envoient pas de webhook et n'appellent ni AfribaPay, ni PixPay, ni PawaPay.

### OTP fictif

Pour tous les opérateurs dont le vrai parcours demande un OTP, utilisez :

```json
{
  "otp": "000000"
}
```

Le premier appel avec un numéro `...000000004` répond :

```json
{
  "error": "otp_required",
  "sandbox": true,
  "simulation": true,
  "ussd_code": "#SANDBOX#",
  "message": "OTP de démonstration requis. Utilisez 000000 avec la même requête."
}
```

Renvoyez ensuite exactement la même requête avec `otp: "000000"`. La réponse sera `HTTP 202` avec `status: "pending"`. Aucun SMS, code USSD réel, transaction ou appel fournisseur n'est déclenché. Tout autre OTP retourne `error: "invalid_otp"`.

### Exemple

```bash
curl -X POST https://www.ashtechpay.com/v1/collect \
  -H "Authorization: Bearer $ASHTECH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 1000,
    "currency": "XAF",
    "country_code": "CM",
    "operator": "MTN Money",
    "phone": "+237000000001",
    "reference": "sandbox-success-001"
  }'
```

Réponse :

```json
{
  "sandbox": true,
  "simulation": true,
  "status": "success",
  "amount": 1000,
    "credited_amount": 950,
    "fee_amount": 50,
  "currency": "XAF",
  "country_code": "CM",
  "operator": "MTN Money",
  "phone": "+237000000001",
  "message": "Paiement confirmé immédiatement"
}
```

Le scénario `pending` est uniquement une réponse initiale de démonstration : aucune transaction n'est créée et aucun statut réel ne sera ensuite disponible à interroger.
