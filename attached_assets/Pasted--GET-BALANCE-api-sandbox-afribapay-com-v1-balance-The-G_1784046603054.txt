GET
HISTORY
api-sandbox.afribapay.com/v1/history?size=100&date_start=2008-12-10&date_end=2024-12-10
Transaction History
AfribaPAY’s Transaction History feature enables businesses to retrieve a complete log of all past transactions processed through the platform.
Each transaction record includes key details such as:
Transaction Date
Amount
Currency
Recipient / Phone Number
Transaction ID / Order ID / Reference ID
Status (SUCCESS, FAILED, PENDING, etc.)
This history helps merchants keep accurate records, monitor payments, and analyze transaction activity over time for reporting and reconciliation.
Request Filters (Optional)
You can filter the transaction history using any of the following parameters:
Date Range (Recommended)
date_start (YYYY-MM-DD) → Start date (inclusive)
Default: today - 3 months
date_end (YYYY-MM-DD) → End date (inclusive)
Default: today
✅ Maximum allowed window: 6 months
Exact Match Filters
transaction_id → Exact match
order_id → Exact match
Phone Number Filter
phone_number → Partial match (digits-only search)
Example: "7701" can match "221770112233"
Type Filter
type → Allowed values: payin | payout
This maps internally to the transaction account_type.
Quick Search (q)
q → Global quick search value
It supports:
✅ Exact match on: transaction_id, order_id, reference_id
🔍 Partial match on: phone_number (digits-only)
Examples
Example 1 — Get latest transactions (default last 3 months)
Plain Text
GET /v1/history
Example 2 — Filter by date range
 View More
Plain Text
GET /v1/history?date_start=2025-01-01&date_end=2025-01-31
Example 3 — Search a specific transaction (exact match)
 View More
Plain Text
GET /v1/history?transaction_id=PIM20250101000001
Example 4 — Search by order ID (exact match)
Plain Text
GET /v1/history?order_id=ORD-839392
Example 5 — Filter by transaction type (payin only)
Plain Text
GET /v1/history?type=payin
Example 6 — Search by phone number (partial match)
Plain Text
GET /v1/history?phone_number=7701
Example 7 — Quick search using q (recommended)
✅ Search by transaction_id / order_id / reference_id (exact)
🔍 Also supports partial phone search
Plain Text
GET /v1/history?q=PIM20250101000001
Or:
Plain Text
GET /v1/history?q=ORD-839392
Or:
Plain Text
GET /v1/history?q=7701

GET
COUNTRIES
api-sandbox.afribapay.com/v1/countries
Data about countries, their currencies, and mobile operators within those countries usied by AfribaPAY. The specific information being selected includes:
country_code: The unique code identifying the country.
country_name: The name of the country.
currency: The currency used in the country.
prefix: The telephone prefix for the country.
taxes: The tax rate or information related to the country.
operator_code: The code of the mobile operator within the country.
operator_name: The name of the mobile operator.
otp_required: A flag indicating whether the operator supports OTP (One-Time Password) services.
ussd_code: The text message sent as part of the OTP process or simply the USSD to validate the transaction.

OTP Verification
OTP Verification – Sandbox Overview
Some providers require an OTP (One-Time Password) after you initiate a transaction.
In sandbox mode, you can enter any 6-digit code to simulate a successful verification — except for a reserved set of test codes that always return a FAILED status.
This allows you to test both happy paths (OTP success) and negative scenarios (OTP failure).
