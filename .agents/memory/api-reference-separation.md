---
name: API reference separation
description: Durable rule for separating integrator references from provider-facing AshTech references.
---

For API-originated collections, the reference sent to every payment provider must be generated by AshTech Pay. A merchant-supplied reference is stored separately in transaction metadata, used for idempotent retries, and returned as `merchant_reference` alongside the AshTech `reference`.

**Why:** Provider-facing references must be controlled by AshTech Pay so callbacks, polling, and cross-provider reconciliation use one trusted identifier without losing the integrator's order reference.

**How to apply:** Keep provider calls and provider webhook lookups on `transactions.reference`; use `metadata.merchantReference` for API idempotency and include it separately in merchant-facing responses and webhooks. OTP sessions must accept the returned AshTech reference and the original merchant reference.
