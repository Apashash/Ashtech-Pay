D’accord. Puisque dans ton projet Ashtech Pay il existe déjà une page de paiement, le prompt doit demander à Replit de connecter l’API Hosted Payment directement à cette page existante, au lieu d’en créer une nouvelle.

Voici donc le prompt corrigé et complet.

⸻

PROMPT POUR REPLIT — UTILISER LA PAGE DE PAIEMENT EXISTANTE

Contexte

Je développe une plateforme de paiement appelée Ashtech Pay.

Mon projet possède déjà une page de paiement fonctionnelle que les utilisateurs peuvent appeler pour effectuer un paiement.

Je veux maintenant créer une API Hosted Payment Page qui va simplement générer un lien et rediriger vers ma page de paiement existante.

Je ne veux pas créer une nouvelle page de paiement.

⸻

1️⃣ Système de clé Hosted Page

Ajouter une clé API spécifique :

hosted_page_key

Exemple :

hp_live_xxxxxxxxx

Chaque marchand doit avoir :

public_key
secret_key
hosted_page_key


⸻

2️⃣ Endpoint API pour créer un paiement

Créer endpoint :

POST /api/v1/hosted-payment/create

Headers :

Authorization: Bearer HOSTED_PAGE_KEY
Content-Type: application/json

Body :

{
  "amount": 5000,
  "currency": "XAF",
  "description": "Paiement commande #123",
  "customer_name": "Jean Dupont",
  "customer_email": "client@email.com",
  "redirect_url": "https://monsite.com/success",
  "cancel_url": "https://monsite.com/cancel"
}

Réponse API :

{
  "status": "success",
  "payment_link": "https://pay.ashtechpay.top/pay/abc123",
  "payment_id": "pay_987654"
}


⸻

3️⃣ Utiliser la page de paiement existante

Quand quelqu’un ouvre :

https://pay.ashtechpay.top/pay/{payment_id}

Le système doit :
	1.	récupérer les données du paiement
	2.	charger la page de paiement existante du projet
	3.	préremplir :

montant
description
email client
nom client

La page existante doit donc accepter un payment_id.

⸻

4️⃣ Paiement terminé

Quand le paiement est terminé :

1️⃣ mettre à jour le statut paiement

success
failed
cancelled

2️⃣ envoyer webhook au marchand

3️⃣ rediriger l’utilisateur.

⸻

5️⃣ Redirection après paiement

Le marchand fournit :

redirect_url
cancel_url

Paiement réussi

Rediriger vers :

redirect_url

Avec paramètres :

?payment_id=pay_123456
&status=success
&amount=5000

Exemple :

https://monsite.com/success?payment_id=pay_123456&status=success


⸻

Paiement échoué

Rediriger vers :

cancel_url

Exemple :

https://monsite.com/cancel?payment_id=pay_123456&status=failed


⸻

6️⃣ Webhook paiement

Créer webhook :

POST /api/v1/webhook/payment

Payload :

{
  "event": "payment.success",
  "payment_id": "pay_987654",
  "amount": 5000,
  "currency": "XAF",
  "status": "success"
}


⸻

7️⃣ Base de données

Créer table :

hosted_payments

Colonnes :

id
merchant_id
payment_id
amount
currency
description
customer_name
customer_email
redirect_url
cancel_url
status
created_at


⸻

8️⃣ Dashboard marchand

Ajouter menu :

Payment Links

Fonctions :
	•	générer lien paiement
	•	copier lien
	•	voir paiements
	•	voir statut

⸻

9️⃣ Documentation développeur

Créer documentation :

docs.ashtechpay.top

Sections :

Authentication

public_key
secret_key
hosted_page_key


⸻

Hosted Payment

Exemple cURL :

curl -X POST https://api.ashtechpay.top/api/v1/hosted-payment/create \
-H "Authorization: Bearer hp_live_xxxxx" \
-H "Content-Type: application/json"


⸻

Résultat attendu

Flux final :

Site marchand
↓
API Ashtech Pay
↓
Lien paiement généré
↓
Client ouvre lien
↓
Page paiement existante Ashtech Pay
↓
Paiement
↓
Webhook envoyé
↓
Redirection vers site marchand


⸻

✅ Cela permettra aux marchands d’intégrer Ashtech Pay très facilement comme :
	•	Stripe
	•	Flutterwave
	•	Paystack
