## Comment utiliser le Skill ?

Vous avez deux possibilités :

1. **Installer le Skill vous-même** en copiant la commande correspondant à
   votre besoin et en l'exécutant dans le terminal de votre projet.
2. **Donner le Skill à l'agent IA de votre choix**. Copiez la commande ou le
   contenu du Skill et transmettez-le à votre agent. Il installera le Skill,
   analysera votre projet et intégrera l'API AshTech Pay en suivant la
   documentation officielle.

Le Skill ne remplace pas votre clé API et ne crée pas votre compte marchand.
Gardez vos clés et vos secrets uniquement dans les variables d'environnement de
votre serveur.

## Avant de commencer

Pour utiliser la Direct API, vérifiez que vous avez :

1. un compte marchand AshTech Pay ;
2. un compte vérifié lorsque le dashboard le demande ;
3. un accès **API activé** par AshTech Pay ;
4. une clé API conservée uniquement sur votre serveur.

Si l'API renvoie `api_not_enabled`, la clé est reconnue mais l'accès API n'est
pas encore activé sur le compte. L'agent ne peut pas contourner cette
activation.

## Installer le Skill ou le donner à un agent IA

Choisissez le Skill adapté à votre intégration. Vous pouvez exécuter la commande
dans le terminal de votre projet ou la transmettre à votre agent IA.

<Tabs>
  <Tab title="Tous les Skills">

Installe tous les Skills publiés par AshTech Pay, y compris les nouveaux Skills
ajoutés plus tard :

```bash
npx skills add https://doc.ashtechpay.com --all
```

  </Tab>
  <Tab title="Direct API">

```bash
npx skills add https://doc.ashtechpay.com --skill ashtech-direct-api
```

Ce Skill couvre les catalogues, les collectes Mobile Money, les paiements
crypto, les statuts et la vérification serveur.

  </Tab>
  <Tab title="Checkout">

```bash
npx skills add https://doc.ashtechpay.com --skill ashtech-checkout
```

Ce Skill couvre Hosted Checkout, les clés `hp_live_...`, l'idempotence des
liens et la confirmation avant livraison.

  </Tab>
  <Tab title="Crypto">

```bash
npx skills add https://doc.ashtechpay.com --skill ashtech-crypto
```

Ce Skill couvre les actifs, réseaux, adresses, `memo/tag`, champs client,
expiration, vérification et webhooks crypto.

  </Tab>
  <Tab title="Mobile Money">

```bash
npx skills add https://doc.ashtechpay.com --skill ashtech-mobile-money
```

Ce Skill couvre les catalogues pays/opérateurs, USSD Push, Wave, OTP SMS et
OTP USSD.

  </Tab>
  <Tab title="Webhooks">

```bash
npx skills add https://doc.ashtechpay.com --skill ashtech-webhooks
```

Ce Skill couvre les signatures, les événements, la déduplication et la
fulfillment idempotente.

  </Tab>
</Tabs>

## Quel Skill choisir ?

| Votre besoin | Skill à installer |
| --- | --- |
| Intégrer AshTech Pay avec plusieurs fonctionnalités | `ashtech` |
| Construire votre propre formulaire et appeler l'API | `ashtech-direct-api` |
| Rediriger le client vers une page de paiement hébergée | `ashtech-checkout` |
| Accepter des paiements crypto | `ashtech-crypto` |
| Accepter Mobile Money avec pays et opérateurs | `ashtech-mobile-money` |
| Recevoir et sécuriser les notifications de paiement | `ashtech-webhooks` |

Si vous hésitez, installez tous les Skills avec la commande **Tous les
Skills**. Pour un seul flux, installez uniquement le Skill correspondant.

## Flux de transaction inclus

Les Skills demandent toujours à l'agent de :

1. inspecter le projet avant de modifier le code ;
2. consulter la documentation officielle actuelle ;
3. garder les clés API et secrets webhook côté serveur ;
4. créer une référence unique ;
5. gérer `pending`, `completed`, `failed`, `cancelled`, `expired` et OTP
   selon la méthode sélectionnée ;
6. vérifier la transaction côté serveur ou par webhook ;
7. dédupliquer les webhooks et empêcher une double livraison ;
8. ne jamais considérer une redirection navigateur comme une confirmation de
   paiement ;
9. ne pas relancer aveuglément une initiation après un timeout.

## Crypto incluse

Le Skill crypto applique notamment les règles suivantes :

- `GET /v1/crypto/assets` pour les actifs et réseaux actifs ;
- `POST /v1/crypto/collect` pour créer le paiement ;
- `customer.email`, `customer.firstName` et `customer.lastName` obligatoires ;
- `asset_code`, réseau, adresse et `memo/tag` conservés exactement ;
- statut serveur et webhook comme sources de vérité ;
- expiration crypto `pending` documentée ;
- aucun crédit ou envoi de commande avant confirmation ;
- aucune monnaie, réseau, adresse ou règle de confirmation inventée.

<Warning>
  N'envoyez jamais une clé API, un secret webhook ou un mot de passe dans le
  chat. Les clés doivent rester dans les variables d'environnement du serveur.
  Les méthodes absentes de la documentation officielle ne sont pas devinées
  par l'agent.
</Warning>

## Après l'intégration

L'agent doit vérifier les points suivants :

1. la clé n'est jamais envoyée au navigateur ;
2. les pays et opérateurs sont chargés depuis le catalogue AshTech Pay, sans
   liste codée en dur ;
3. chaque paiement possède une référence unique ;
4. un paiement `pending` n'est pas traité comme un paiement confirmé ;
5. les webhooks sont vérifiés et dédupliqués ;
6. un timeout ne relance pas automatiquement une nouvelle collecte ;
7. les tests, le build et les erreurs API sont vérifiés.
