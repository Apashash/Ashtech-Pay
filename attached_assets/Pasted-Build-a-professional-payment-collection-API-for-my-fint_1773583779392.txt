Build a professional payment collection API for my fintech platform called Ashtech Pay.

The goal is to create a REST API that allows merchants to collect Mobile Money payments directly on their website or mobile application without redirecting customers to another page.

The API must act as a middleware between two payment providers:
- Afribapay
- Pixpay

Merchants should only integrate Ashtech Pay API and never interact directly with Afribapay or Pixpay.

Technical requirements:

1. Backend
Use Node.js with Express.

2. Database
Use Supabase to store:
- merchants
- api_keys
- transactions
- providers configuration
- fees configuration

3. API Authentication
Each merchant must have an API key.
Requests must include:

Authorization: Bearer API_KEY

4. Main Endpoint

POST /v1/collect

Example request:

{
  "amount": 5000,
  "currency": "XAF",
  "phone": "670000000",
  "operator": "MTN",
  "reference": "ORDER123"
}

5. Smart Provider Routing

The API must dynamically choose the provider based on a database configuration table.

Example table "providers":

operator | provider | active
MTN      | afribapay
ORANGE   | pixpay

If the configuration changes in the database, routing must update automatically without code changes.

6. Dynamic Fees

Create a table "fees":

operator | fee_percent
MTN      | 1.5
ORANGE   | 2

The API must calculate fees automatically when processing a payment.

If the fee is changed in the database, it should apply immediately to all merchants.

7. Provider Integration

Create two service modules:

services/afribapay.js
services/pixpay.js

Each module must handle API calls to the respective provider.

8. Unified Response Format

Regardless of the provider used, the API must always return the same response format:

{
  "status": "pending",
  "transaction_id": "txn_123456",
  "amount": 5000,
  "currency": "XAF",
  "operator": "MTN"
}

9. Webhooks

Create a webhook endpoint:

POST /v1/webhook/provider

This endpoint will receive payment status updates from Afribapay and Pixpay.

Update the transaction status in Supabase when a webhook is received.

10. Transaction Endpoint

GET /v1/transaction/:id

Return transaction details.

11. Project Structure

src/
  controllers/
  routes/
  services/
  middleware/
  config/
  database/

12. Security

Add:

- API key validation middleware
- request validation
- error handling
- transaction logging

13. SDK Example

Provide a simple JavaScript integration example for merchants:

fetch("https://api.ashtechpay.top/v1/collect", {
  method: "POST",
  headers: {
    "Authorization": "Bearer API_KEY",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    amount: 5000,
    currency: "XAF",
    phone: "670000000",
    operator: "MTN"
  })
})

14. Important Requirement

The payment must happen directly on the merchant website.

Customers must never be redirected to Ashtech Pay pages.

Ashtech Pay acts only as a backend payment gateway.

15. Scalability

Structure the project in a way that allows adding more providers in the future.
